## Quick checks a reviewer can run

```bash
grep -a "successful demos" v1/logs/v1_gen.log | tail -1      # 300/388 (77.3%)
grep -o "Train Epoch [0-9]*" v1/logs/v1_train.log | tail -1   # Train Epoch 2000
grep -c Traceback v1/logs/v1_train.log                         # 0
grep -a -E "Successful trials|Success rate" v1/logs/v1_eval.log  # 48 out of 50, 0.96
```

(If a log is stored as `.log.gz`, use `zgrep` instead of `grep`.)

## Not in git, and why

The generated dataset (145 MB) and the model checkpoints are larger than GitHub allows. Their SHA-256 hashes are in
`logs/checksums.txt`, so the copies kept on the GPU machine / SJSU HPC can be shown to be the same files.

## Questions to expect, and the answer

| Question | Answer |
|---|---|
| Is 96% just luck? | 95% Wilson interval is 86.5–98.9% for 48/50. v4 uses 100 rollouts per arm to tighten this. |
| Why only the final checkpoint? | v1 is a reference run; v4 evaluates checkpoints per arm. Stated as a limitation. |
| Isn't this just NVIDIA's tutorial? | Yes, on purpose: v1 is the course's "Reproduce" step. The research contribution starts in v2 (scripted operator with latency/occlusion/jitter injected into what the operator perceives). |
| Why `--device cpu`? | We used the commands from NVIDIA's documented GR-1 Mimic workflow, which run generation and evaluation with `--device cpu`; training uses the GPU. |
